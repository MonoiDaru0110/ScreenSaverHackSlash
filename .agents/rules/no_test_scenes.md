# 開発・検証・コマンド実行ルール

## 1. テスト用一時ファイルの生成および検証実行の禁止
- 動作検証やテストを目的とした一時的なシーン（`test_*.tscn`）やスクリプト（`test_*.gd`）、ログファイル等をプロジェクト内に生成しないこと。
- Godot のヘッドレス実行コマンド（`godot.exe --headless ...` 等）を検証目的で安易に呼び出さないこと。
- リポジトリおよび作業ディレクトリを常に清潔に保つこと。

## 2. ターミナルコマンドの抑制と内部ツールの完全優先
ユーザーへの確認ダイアログの乱発を防ぎ、快適な開発体験を保つため、以下のルールを徹底すること：
- **ファイル閲覧**: PowerShell の `Get-Content` や `cat` は使わず、確認不要のビルトインツール `view_file` を使用すること。
- **ファイル内検索**: `Select-String` や `grep`、`git grep` は使わず、確認不要のビルトインツール `grep_search` を使用すること。
- **ファイル一覧・探索**: `Get-ChildItem` や `dir`、`ls` は使わず、確認不要のビルトインツール `find_by_name` や `list_directory` を使用すること。
- **ターミナル実行（run_command）**: 本当に必要な最小限の操作に限定すること。
